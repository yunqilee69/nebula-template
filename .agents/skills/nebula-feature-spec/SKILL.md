# Nebula 功能说明书编写

编写 Nebula 功能说明书，作为前后端开发的标准文档。包含功能概述、接口设计、编码要求、测试用例（TDD）等。

## 触发词

- "编写功能书"
- "功能说明"
- "功能文档"
- "开发计划"

---

## Steps

### Step 1: 创建文档

**动作**: 在项目目录创建功能书文件

**文件路径**: `docs/dev/{yyyy-MM-dd}-{功能说明}.md`

**命名规则**:
- 日期格式：`yyyy-MM-dd`
- 功能说明：简短中文描述，用连字符分隔
- 示例：`docs/dev/2025-01-15-用户头像上传.md`

**完成条件**: 文件创建成功

---

### Step 2: 编写功能概述

**内容**:
- 功能描述
- 目标用户
- 业务价值

**模板**:
```markdown
## 1. 功能概述

### 1.1 功能描述
{功能描述}

### 1.2 目标用户
{目标用户}

### 1.3 业务价值
{业务价值}
```

**完成条件**: 功能概述编写完成

---

### Step 3: 编写功能点清单

**内容**:
- 序号、功能点名称
- 优先级（P0/P1/P2）
- 涉及模块
- 状态（待开发）

**模板**:
```markdown
## 2. 功能点清单

| 序号 | 功能点 | 优先级 | 涉及模块 | 状态 |
|---:|---|---|---|---|
| 1 | {功能点1} | P0 | {模块} | 待开发 |
| 2 | {功能点2} | P1 | {模块} | 待开发 |
```

**完成条件**: 功能点清单编写完成

---

### Step 4: 设计接口

**内容**:
- 接口列表（方法、路径、说明）
- 请求结构
- 响应结构
- 状态码

**模板**:
```markdown
## 3. 接口设计

### 3.1 接口列表

| 序号 | 接口名称 | 方法 | 路径 | 说明 |
|---:|---|---|---|---|
| 1 | {接口名} | POST | /api/{module}/{resource} | {说明} |

### 3.2 请求结构

**请求体**:
```json
{
  "field1": "value1",
  "field2": "value2"
}
```

### 3.3 响应结构

**响应体**:
```json
{
  "code": 0,
  "message": "success",
  "data": {
    "id": "xxx",
    "name": "xxx"
  }
}
```

### 3.4 状态码

| 状态码 | 说明 |
|---|---|
| 0 | 成功 |
| {错误码} | {错误说明} |
```

**完成条件**: 接口设计编写完成

---

### Step 5: 定义数据模型

**内容**:
- 涉及的 Entity（新增/修改）
- DTO 结构
- Req/Resp 结构

**模板**:
```markdown
## 4. 数据模型

### 4.1 涉及 Entity

| Entity | 模块 | 变更类型 | 说明 |
|---|---|---|---|
| UserEntity | auth-core | 修改 | 新增 avatarFileId 字段 |

### 4.2 新增 DTO

```java
@Data
@Schema(description = "xxx DTO")
public class XxxDto {
    @Schema(description = "字段1")
    private String field1;
}
```

### 4.3 新增 Req/Resp

```java
@Data
@Schema(description = "xxx 请求")
public class CreateXxxReq {
    @Schema(description = "字段1")
    private String field1;
}
```
```

**完成条件**: 数据模型定义完成

---

### Step 6: 编写编码要求

**内容**:
- 设计模式要求
- 前端路由
- 命名约定
- 异常处理
- 规范引用

**模板**:
```markdown
## 5. 编码要求

### 5.1 设计模式
- 使用{模式名}模式实现{用途}

### 5.2 前端路由
- `/{module}/{page}` - {页面说明}

### 5.3 命名约定
- Controller: `{Module}Controller`
- Service: `{moduleName}{Action}`
- DAO: `{Module}DAO`

### 5.4 异常处理
- {异常场景}: `{Module}ErrorInfo.{ERROR_CODE}`

### 5.5 规范引用
- 分层规范: @docs/spec/02-layering.md
- 命名规范: @docs/spec/03-naming.md
- 异常处理: @docs/spec/07-exception.md
```

**完成条件**: 编码要求编写完成

---

### Step 7: 编写测试用例

**内容**:
- 单元测试列表
- Controller 测试列表
- 集成测试列表
- TDD 要求：先写测试再实现

**模板**:
```markdown
## 6. 测试用例（TDD）

> ⚠️ **先写测试，再实现功能**

### 6.1 单元测试

| 序号 | 测试类 | 测试方法 | 测试场景 |
|---:|---|---|---|
| 1 | `{Module}ServiceTest` | `test{Action}Success` | 正常场景 |
| 2 | `{Module}ServiceTest` | `test{Action}Error` | 异常场景 |

### 6.2 Controller 测试

| 序号 | 测试类 | 测试方法 | 测试场景 |
|---:|---|---|---|
| 1 | `{Module}ControllerTest` | `test{Action}` | MockMvc 测试 |

### 6.3 集成测试

| 序号 | 测试类 | 测试场景 |
|---:|---|---|
| 1 | `{Module}IT` | 完整流程测试 |

### 6.4 TDD 流程

1. 编写单元测试（预期失败）
2. 实现最小代码使测试通过
3. 重构代码
4. 重复直到所有测试通过
```

**完成条件**: 测试用例编写完成

---

### Step 8: 补充用例

**内容**:
- 典型使用场景
- 边界情况
- 异常情况

**模板**:
```markdown
## 7. 用例

### 7.1 典型场景

**场景1: {场景名}**
1. 用户进入{页面}
2. 执行{操作}
3. 系统返回{结果}

### 7.2 边界情况

- {边界情况1}: {处理方式}
- {边界情况2}: {处理方式}

### 7.3 异常情况

- {异常情况1}: 抛出{异常}，提示{消息}
```

**完成条件**: 用例编写完成

---

### Step 9: 编写附录

**内容**:
- 相关模块
- 参考规范
- 开发日志（创建时间）

**模板**:
```markdown
## 8. 附录

### 8.1 相关模块
- `nebula-{module}-local` - {模块说明}

### 8.2 参考规范
- `docs/spec/01-architecture.md` - 架构规范
- `docs/spec/02-layering.md` - 分层规范

### 8.3 开发日志
- {yyyy-MM-dd} - 创建功能书
```

**完成条件**: 附录编写完成

## 禁止行为

- ❌ 功能书未包含测试用例
- ❌ 测试用例未注明 TDD 要求
- ❌ 编码要求未引用规范文件
- ❌ 接口设计缺少请求/响应结构
- ❌ 数据模型未注明所属模块
