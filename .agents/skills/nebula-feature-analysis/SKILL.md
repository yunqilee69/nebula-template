# Nebula 功能分析

与用户问答确认功能需求，输出明确的功能点清单。被 `/nebula-dev-guide` 调用，或用户直接调用进行需求分析。

## 触发词

- "分析功能"
- "需求分析"
- "设计功能"
- "开发新功能"

---

## Steps

### Step 1: 收集需求

**动作**: 引导用户描述需求

**话术**:
```
我理解你需要开发{功能}。请描述以下内容：
1. 功能的目标用户是谁？
2. 主要解决什么问题？
3. 有没有参考的系统或流程？
```

**完成条件**: 用户提供了初始需求描述

---

### Step 2: 模块分析

**动作**: 分析涉及的 Nebula 模块

**模块清单**:
| 模块 | 功能 | 典型场景 |
|---|---|---|
| `auth` | 用户认证、角色权限、组织架构 | 登录注册、权限控制、OAuth2 |
| `storage` | 文件上传、分片上传、鉴权下载 | 头像上传、附件上传 |
| `dict` | 数据字典类型与字典项 | 状态枚举、下拉选项 |
| `param` | 系统参数管理 | 开关配置、阈值设置 |
| `notify` | 公告、通知、站内信 | 首页公告、弹窗通知 |
| `scheduler` | 任务调度 | 定时任务、异步任务 |
| `audit` | 审计日志 | 操作留痕 |

**话术**:
```
根据你的需求，分析涉及以下模块：
- {模块1}: {使用原因}
- {模块2}: {使用原因}

是否正确？
```

**完成条件**: 用户确认涉及的模块

---

### Step 3: 功能点拆分

**动作**: 将需求拆分为原子功能点

**规则**:
- 每个功能点只做一件事
- 功能点之间无依赖或明确依赖关系
- 标注优先级（P0 必须、P1 重要、P2 可选）

**话术**:
```
我已将功能拆分为以下功能点：

| 序号 | 功能点 | 优先级 | 涉及模块 |
|---:|---|---|---|
| 1 | {功能点1} | P0 | {模块} |
| 2 | {功能点2} | P1 | {模块} |
| 3 | {功能点3} | P2 | {模块} |

请逐项确认每个功能点是否正确。
```

**完成条件**: 用户对每个功能点确认"是"

---

### Step 4: 技术方案

**动作**: 确定技术实现方案

**确认项**:
1. **架构模式**: `local`（单体）或 `remote`（微服务）
2. **数据流**: Req → Command → Entity → Dto → Resp
3. **存储方案**: 新增表还是复用现有表
4. **接口风格**: RESTful

**话术**:
```
技术方案确认：
- 架构模式: {local/remote}
- 数据流: {描述}
- 存储方案: {描述}

是否确认？
```

**完成条件**: 用户确认技术方案

---

### Step 5: 输出功能点清单

**动作**: 输出 JSON 格式功能点清单

**格式**:
```json
{
  "featureName": "{功能名称}",
  "description": "{功能描述}",
  "targetUser": "{目标用户}",
  "modules": ["{模块1}", "{模块2}"],
  "mode": "local",
  "features": [
    {"id": 1, "name": "{功能点1}", "priority": "P0", "confirmed": true},
    {"id": 2, "name": "{功能点2}", "priority": "P1", "confirmed": true}
  ],
  "techSolution": {
    "mode": "local",
    "storage": "{存储方案}",
    "dataFlow": "{数据流描述}"
  }
}
```

**完成条件**: 功能点清单输出完成

---

## 完成条件汇总

| Step | 完成条件 |
|---|---|
| Step 1 | 用户提供了初始需求描述 |
| Step 2 | 用户确认涉及的模块 |
| Step 3 | 用户对每个功能点确认"是" |
| Step 4 | 用户确认技术方案 |
| Step 5 | 功能点清单输出完成 |

**最终完成条件**: 所有 Step 完成，用户对功能点清单整体确认

---

## 禁止行为

- ❌ 用户未描述需求就假设功能点
- ❌ 功能点描述模糊或有歧义
- ❌ 用户未确认就进入下一步
- ❌ 跳过模块分析直接拆分功能点
